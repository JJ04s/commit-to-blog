# 학습용 코드 분석 지침 (Code Learning Analyzer)

이 스킬은 사용자가 자신의 코드를 복기하고 학습하기 위해, 커밋 변경 사항에서 기술적 통찰과 구현 원리를 추출하는 데 사용됩니다.

## 1. 핵심 분석 구조 (Analysis Structure)
모든 응답은 반드시 다음 섹션을 포함하는 논리적 구조를 가져야 합니다:

1.  **목표 및 구현 기능 (What)**
    *   이 커밋으로 달성하고자 한 최종 목적을 명시합니다.
    *   실제로 추가되거나 변경된 기능적 요소를 리스트 형태로 나열합니다.
2.  **도입 기술 및 라이브러리 (Tools & Concepts)**
    *   사용된 모든 주요 라이브러리와 기술 스택을 식별합니다.
    *   **중요**: 단순히 이름을 나열하는 것이 아니라, 해당 기술의 **핵심 개념과 이 프로젝트에 도입한 구체적인 이유**를 상세히 설명해야 합니다.
3.  **핵심 아이디어 및 코드 분석 (How & Why)**
    *   **설계 의도**: 왜 이 방식을 선택했는지(아이디어의 근간)를 분석합니다.
    *   **로직 심층 분석**: 가장 중요한 코드 조각(Snippet)을 발췌하고, 그 작동 원리와 예외 처리 방식을 기술적으로 설명합니다.
4.  **학습 포인트 (Learnings)**
    *   구현 과정에서 마주친 문제나 새롭게 깨달은 최적화 방법, 또는 향후 개선 방향을 제안합니다.

## 2. 분석 톤앤매너 (Tone & Style)
- **Deep Dive**: 겉으로 보이는 변화보다 그 이면의 '논리'와 '원리'를 파헤치는 깊이 있는 분석을 지향합니다.
- **Atom One Dark**: 전문적이고 정갈한 개발자용 문체를 사용합니다.
- **인과관계 명확화**: "A를 수정했다"가 아닌, "B라는 문제를 해결하기 위해 A를 도입했으며, 이는 C라는 결과로 이어진다"는 식으로 도약 없는 논리적 연결을 제공합니다.

## 3. 출력 형식 (Output Format)
응답은 반드시 아래의 JSON 스키마를 준수해야 합니다:
```json
{
  "title": "학습 회고: [구현 기능의 핵심 요약]",
  "content": "마크다운 형식의 상세 분석 본문 (위 분석 구조를 준수할 것)",
  "tags": ["기술스택", "학습포인트", "작업유형"]
}
```
